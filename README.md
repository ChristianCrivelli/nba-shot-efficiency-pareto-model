# Pareto 2v3 — The Efficient Frontier of Sports

A decision-science model that treats basketball shot selection as
portfolio optimization: each shot zone is an "asset" with a return
(expected points) and a risk (variance of that outcome), and the project
finds the Pareto-efficient frontier of that tradeoff — including the
practical break-even threshold between 2-point and 3-point shooting
(`FG2%_break-even = 1.5 × FG3%`).

For the findings and the full methodology, start with:

- **`workstream4_synthesis/synthesis_and_strategy.md`** (or the
  coaching-facing `.pdf` next to it) — the project's conclusions, written
  for coaches and analysts.
- **`docs/report.md`** — working methodology notes: data sources, every
  scoping decision, and what's still open.
- **`docs/project_description.md`** — the original project brief.

## Repo layout

Organized by workstream, per the project's four-workstream spec
(workstream 3's math has no scripts of its own — it's folded into 1, 2,
and 4):

```
workstream1_zones/       Zone-level Pareto-efficiency heatmaps
                          (zone_efficiency.py, build_zone_heatmaps.py,
                          court_viz.py)

workstream2_mega_graph/  Population-level "2 vs 3" scatter plots, static
                          + interactive (load_kaggle_season_totals.py,
                          build_2v3_plots.py, build_2v3_interactive.py)

workstream4_synthesis/   The coaching-facing write-up and its build
                          scripts (synthesis_and_strategy.md/.pdf,
                          build_breakeven_trend.py, build_synthesis_pdf.py)

shared/                  Code used by more than one workstream
                          (player_headshots.py, test_headshots_smoke.py)

outputs/                 Generated chart artifacts (PNG/HTML) — not
                          committed source, regenerated by the scripts
                          above

data/                    Raw and derived CSVs, unchanged by this reorg
                          (shot logs, season totals, the Kaggle dataset
                          under data/515/, the headshot cache)

legacy/                  Superseded/exploratory scripts kept for the
                          record (season_totals.py, sample_data.py) —
                          not part of the current pipeline

docs/                    report.md and project_description.md
```

Every script resolves its data/output paths relative to the repo root
(via a `REPO_ROOT = Path(__file__).resolve().parents[1]` at the top of
the file), so each one runs correctly either from the repo root
(`python workstream1_zones/zone_efficiency.py`) or from inside its own
folder (`python zone_efficiency.py`).

See `docs/report.md` for the full history of how this repo got here,
including a note on this 2026-09-17 reorganization itself.
